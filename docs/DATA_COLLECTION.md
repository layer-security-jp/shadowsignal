# データ収集仕様

ShadowSignalは、利用者が指定した`--target-host`を端末内で名前解決し、そのIPアドレスと
443番ポートに一致する通信だけを取得します。全端末の生パケットをAPIへ転送する仕組みでは
ありません。

## 端末内でのみ扱う情報

- 指定された宛先ホスト名と、名前解決後のIPアドレス
- ローカルIP、ローカルポート、リモートポート
- OSが提供できる場合のプロセス名・親プロセス名
- TLS ClientHelloから取得できる場合のSNI
- パケットの絶対取得時刻
- パケット取得用の一時ファイル

これらは対象フローの抽出、通信方向の判定、対象端末内の結果表示にだけ使用します。

## APIへ送信する情報

- 観測ごとに生成するランダムな`observation_id`
- `tcp`または`quic`のトランスポート区分
- 同一観測に含める匿名フローの区切り
- `l4_segment`という観測粒度
- 最初の対象イベントからの相対時刻（10ミリ秒単位）
- 方向（`in`または`out`）
- 暗号化トランスポートデータサイズ（32バイト単位、最大1536バイト）

観測窓は最大180秒です。1フロー最大512件、1観測最大16フロー・2048件に制限します。
絶対取得時刻は相対時刻へ変換し、元のパケットサイズは送信前に量子化します。APIは
フローごとに独立して判定し、別フローのイベントを1本の時系列として扱いません。

## APIへ送信しない情報

- 宛先ホスト、宛先IP、送信元IP、MACアドレス、ポート番号
- プロセス名、親プロセス名、PID、ユーザー名、ファイルパス
- 顧客名、端末ID、ハードウェアID、広告ID、絶対時刻
- DNS内容、TLS SNI、ALPN、証明書、TCP sequence/acknowledgement
- 生パケット、パケットヘッダー、暗号化されたペイロード断片
- プロンプト、応答、ファイル内容、HTTPヘッダー、Cookie、認証情報
- 対象端末内の既知AI宛先判定、ベンダー名、製品名

APIはスキーマにないフィールドを拒否します。

## Windowsでの一時取得

OS標準のパケット取得機能を使い、解決済みIPと443番の一時的な取得条件を設定します。
各パケットの先頭最大512バイトを一時ファイルへ保存します。ShadowSignalはネットワーク・
トランスポートヘッダーと、取得できる場合はTLS ClientHelloのSNIを端末内で解析します。
暗号化されたデータ断片やSNIをAPIへ送信せず、一時ファイルは処理終了前に削除します。

OS側のパケット取得設定がすでに使用されている場合は、上書きせず処理を中止します。

## macOSでの一時取得

OS標準の機能で宛先IPごとの実際の経路を確認し、必要なネットワークインターフェースへ
対象IPと443番の取得条件を設定します。

各パケットの先頭最大512バイトを一時ファイルへ保存し、取得できる場合はTLS ClientHelloの
SNIを端末内で解析して、対象ホストとフローを照合します。暗号化されたデータ断片やSNIを
APIへ送信せず、解析後に一時ファイルを削除します。複数経路がある場合は取得時刻を端末内で
統合してから相対時刻へ変換します。

## ローカルダッシュボード

ダッシュボードは`127.0.0.1`だけで待ち受け、起動ごとにランダムなリクエストトークンを
生成します。CORSを許可せず、判定履歴を保存しません。画面には次を明確に分離して表示します。

- 実際にAPIへ送った通信形状JSON
- 対象端末内にだけ存在する宛先・プロセス情報
- APIが返した形状判定
- 対象端末内で結合した最終判定

APIキーはブラウザへ埋め込みません。

## API基盤で観測され得る情報

リクエスト本文には宛先・IP・絶対時刻を含めません。ただし通常のHTTPS通信と同様、
API基盤やネットワーク事業者は、接続元IP、接続時刻、通信量などを観測し得ます。
ShadowSignalアプリケーションはリクエスト本文をログ出力しません。

## 送信前確認

```bash
shadowsignal capture --target-host api.anthropic.com --duration 45 --dry-run
```

`--dry-run`ではローカル取得と通信形状への変換まで実行し、API通信を行わず、送信予定の
JSON全体を標準出力へ表示します。
